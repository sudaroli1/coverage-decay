## 1. Corrections made during this session

Six, in the order found. Each is recorded because the sequence is itself evidence that
the numbers were interrogated rather than accepted.

| # | Fault | Effect |
|---|---|---|
| 1 | Suppression and relaxation tests were asymmetric | 1,204 / 287 → 1,098 / 245 |
| 2 | Predicate counting missed value-level suppression | +510 suppressions |
| 3 | Predicate strings retained condition-tree syntax, so unchanged predicates that *moved* compared as changed | §5 totals fell ~11% |
| 4 | `.count('CTX:NEG')` counted duplicate predicates; set comparisons did not | 270 / 8,234 steps affected |
| 5 | A catch-all selection (`EQ '*'`) counted as coverage growth | expansion-with-guard 111 → 73 |
| 6 | `PATH_FIELDS` missed case variants and modifier suffixes | 36 values misrouted |
| 7 | Case-variant dedup counted as relaxation (§6.3.1) | not corrected; biases ratio downward |
| 8 | Metadata `commits[]` is **not** positionally aligned with PGIR `version_index` | §7 corroboration was wrong (78% → 30.9%) |

**Correction 8 in detail — a silent join error.** Joining commit messages by treating
`version_index` as a position in the lineage's `commits` list matches the correct commit
only **19.7%** of the time. The cause is the filter in the prior work's
`load_analysis_lineages`, which drops versions whose SPL will not parse (the 4,358 vs
4,204 discrepancy Elena Long described): `version_index` counts the *filtered* version
list while `commits` is *unfiltered*, so the two diverge after the first dropped version.
Joins between the two must go through commit **date** or **hash**. Anyone building on this
bundle should be warned — the failure is silent and produces a plausible-looking number.

**Do not cite** 1,204 / 287 / 4.2:1, 1,098 / 245 / 4.5:1, 1,608 / 299, 4,042
field-additions, 5,889 or 5,233 path values, 73.7% or 64.5% enterable, or any
"median persistence" figure.

### 1.1 Value-level suppression (correction 2)

In PGIR a list-valued field is a *single* predicate holding many literals:

```
P:Image|IN|(('S','*mshta'),('S','*msiexec'),('S','*regsvr32'))|CTX:NEG
```

Appending a value to that list is a suppression that leaves the predicate count
unchanged. Exclusion growth is therefore measured at predicate *and* value level.

Hand inspection confirmed the class is real: `lineage_00531 v1→v2` turns
`SourceImage EQ '*\csrss.exe'` into `SourceImage IN ('*\csrss.exe', '*unknown process*')`.

**Methodological consequence.** Prior work diffs structure and observes the predicate
mechanism only. A structural measurement of rule evolution therefore undercounts
narrowing.

### 1.2 A third mechanism, not detected

Exclusion breadth also grows by *generalisation* of an existing value. In
`lineage_02634 v4→v5`, `C:\Windows\System32\csrss.exe` and `MBAMService.exe` are
replaced by `C:\Program Files\*` and `C:\Program Files (x86)\*` — literal count barely
moves while the excluded region goes from two named binaries to every executable under
Program Files. Inspection of the rewrite stratum suggests this is uncommon; it is
**not measured**, so the counts below are a lower bound.

### 1.3 Compound revisions, not detected

`V045` in the validation sample withdraws one exclusion (`WerFault.exe`) and adds
another (`Sysmon.exe`) in a single revision. Net counts read zero change. Any
net-count detector — this one and the prior work's alike — is blind to these.

## 4. Persistence

Clock starts at the commit adding the exclusion. Event = a later revision in the same
lineage where **both** the distinct exclusion-predicate count and the exclusion literal
count return to or below their pre-suppression values. Steps under 1 day dropped
(same-PR sequencing); 58 of 1,642 have no measurable duration.

```
n = 1584   removed = 203   censored = 1381 (87.2%)
```

### 4.1 Kaplan–Meier, all suppressions (n = 1,584)

| Horizon | Still in place |
|---:|---:|
| 30 days | 0.966 |
| 90 days | 0.949 |
| 180 days | 0.933 |
| 365 days | 0.899 |
| 730 days | 0.870 |
| 1095 days | **0.867** |

- **KM median survival: undefined** — the curve never reaches 0.50.
- **RMST over 3 years: 978 of 1,095 days** (89% of the window).
- **Median follow-up (reverse KM): 1,296 days** — longer than the reporting horizon,
  so the flat tail is not an artefact of short observation.

> **Never report a "median persistence."** The `days` column mixes 1,381 censored
> durations with 203 event times; its median is median *follow-up*.

### 4.2 Removal is a closing window

| | share of the 203 removals |
|---|---:|
| within 180 days | 52% |
| within 365 days | 76% |

The hazard concentrates early and approaches zero after roughly two years.

**Proposed mechanism.** Review is triggered by an alert firing. A suppressed rule stops
firing on the suppressed pattern, so the suppression removes the signal that would
prompt its own review.

### 4.3 Null result — persistence is independent of coverage redundancy

| group | n | censored |
|---|---:|---:|
| sole coverage | 71 | 63 |
| redundant coverage | 1,268 | 1,093 |
| untagged (excluded from the test) | 245 | 225 |

**Log-rank: p = 0.4927, statistic = 0.47** (n = 1,339). Curves indistinguishable. The
null has now held across three runs at p = 0.96, 0.31 and 0.49 on successively larger
samples.

Reported as a finding: nothing in the observed process is weighted by consequence.
The 71 sole-coverage events remain relevant as a **severity** argument — those
exclusions have no fallback detection — but not as a persistence argument.

## 5. What is excluded (answering Dacier)

Dacier's objection: narrowing need not cost coverage if the excluded attribute is one
an adversary cannot assume. **Supersedes the 665-field / 90.2% figures sent to him; a
correction is owed, and §5.3 concedes more to his position than the original did.**

### 5.1 Which attribute is excluded on

3,606 field-additions across 1,642 suppressions. A field-addition is an exclusion
predicate present in `sig_b` and absent from `sig_a`, counted per revision step.

| class | count | share |
|---|---:|---:|
| 1 — process / file / registry content | 3,101 | 86.0% |
| 2 — network identity | 362 | 10.0% |
| 3 — account identity | 38 | 1.1% |
| 4 — system-assigned | 39 | 1.1% |
| 6 — operation parameters (adversary-selected) | 66 | 1.8% |
| 5 — unclassified | 0 | 0.0% |
| **total** | **3,606** | |

98.9% fall in classes an adversary can influence. **This number alone is weak** — with
almost everything in one bucket, "influenceable" barely discriminates. §5.2 carries the
claim.

### 5.2 Whether the exclusion can actually be entered

Influenceability has a cost. `Image|endswith: '\chrome.exe'` is entered by naming a
file; `Image: 'C:\Program Files\Windows Defender\MsMpEng.exe'` requires privileged
write. Restricted to path-valued fields:

| anchor | count | share |
|---|---:|---:|
| bare name or suffix | 3,105 | 58.2% |
| protected path | 1,759 | 33.0% |
| user-writable path | 316 | 5.9% |
| other absolute path | 128 | 2.4% |
| empty | 21 | 0.4% |
| other relative path | 7 | 0.1% |
| **total** | **5,336** | |

| | count | share |
|---|---:|---:|
| **Enterable without privilege** | **3,421** | **64.1%** |
| Requires privileged write | 1,759 | 33.0% |

**Argument for counting leading-wildcard values as free.** A value beginning `*`
derives from a Sigma `endswith`/`contains` match, which is location-independent: an
exclusion on `*\Windows\System32\csrss.exe` is satisfied by
`C:\Users\<user>\tmp\Windows\System32\csrss.exe`, which an unprivileged process can
create. This inference is load-bearing for the 58.2% and must be argued explicitly.
Values of the form `*C:\...` are excluded from it — a drive letter cannot appear
mid-path.

### 5.3 What this concedes to Dacier

A third of path exclusions require privileged write access to a protected directory.
For those his analogy holds: the exclusion is precise and entering it is not free. The
supported claim is therefore narrower than "narrowing removes coverage" — it is that
**roughly two thirds of file-path exclusions can be entered by an unprivileged process
that chooses a filename.**

## 5.6 Temporal structure

Added after the cumulative-burden figure showed a step change that needed explaining.

### 5.6.1 The ratchet is not corpus growth

Cumulative net exclusions rise from ~0.05 to ~0.57 **per active rule** between 2017 and
2026, a tenfold increase. The accumulation is not an artefact of the corpus growing.

### 5.6.2 The ratchet is not bulk editing

| | |
|---|---|
| Suppressions on the 20 busiest days | 326 / 1,642 (**20%**) |
| Distinct lineages contributing | **524** (≈3.1 suppressions each) |
| **Ratio excluding the 20 busiest days** | **4.9 : 1** (headline 5.4 : 1) |

Busiest days are spread across 2022–2025 rather than clustering. The sensitivity result
disposes of the bulk-editing objection.

### 5.6.3 The 2021–2023 calendar cluster is activity, not behaviour

58% of suppressions fall in Oct 2021 – Jan 2023. But total revision activity peaks in
the same window (up to ~2,500 revisions/month against a baseline of a few hundred).
Suppression *share* in the window is 0.083 against 0.058 elsewhere — a 1.4× lift, not a
regime change. **Belongs in §4.1 as one sentence, not in threats to validity.**

### 5.6.4 Rule age at suppression

| percentile | days |
|---|---:|
| 25th | 105 |
| 50th | **492** |
| 75th | 956 |
| 90th | 1,379 |

24% of suppressions occur within 90 days of rule creation and 44% within a year, so
there is a real early-tuning spike — but the median rule is 16 months old when an
exclusion is added, and 56% of suppressions occur after the first year. Suppression is
not confined to initial tuning.

Paired with §4.1 this gives the lifecycle sentence: **an exclusion arrives around
sixteen months into a rule's life and outlives everything that follows.**

### 5.6.5 Suppression is a growing share of maintenance

Restricted to the 77 months with ≥50 revisions (small denominators produce spurious
shares of 0.3–0.5 in the sparse tail):

| | first half | second half | Spearman |
|---|---:|---:|---|
| all suppressions | 0.033 | 0.079 | rho = +0.455, p = 3.2e-05 |
| predicate-level | 0.017 | 0.057 | rho = +0.535, p = 5.4e-07 |
| value-level | 0.015 | 0.022 | rho = +0.208, p = 0.069 (n.s.) |

**A mechanical explanation was tested and refuted.** Value-level suppression requires an
existing list to append to, so opportunities for it grow structurally as rules
accumulate filters; that hypothesis predicts the value-level share should rise. It does
not. The trend is carried by the predicate mechanism, which has no such dependency.

The rise is therefore behavioural: as the corpus matures, maintenance shifts from
writing detections toward narrowing them.

> **Caveat to state explicitly.** Months are not independent, so Spearman's p is
> optimistic. Lead with the effect size (a doubling, and 3.4× for predicate-level) and
> report serial correlation as a limitation.

## 6. Detector validation

### 6.1 Design

120 revision steps: 60 classified as suppressions, 60 drawn from the four negative
strata (15 each). Items shuffled and presented as predicate diffs only. **Commit
messages were withheld** so that the corroboration measure in §7 remains independent of
the labels. A single rater (the author) assigned S / N / U. Arms were recomputed under
the final definitions after adjudication; the items themselves are unchanged, and a
human judgement about a diff does not expire when the classifier is corrected.

### 6.2 Precision

| | |
|---|---:|
| Decided positives | 58 |
| True suppressions | 48 |
| False positives | 10 |
| **Precision** | **0.828**  95% CI (Wilson) **[0.711, 0.904]** |

### 6.3 Recall (stratified estimate)

| stratum | false negatives | rate | 95% CI | stratum size | scaled |
|---|---|---:|---|---:|---:|
| expansion-with-guard | 1/5 | 0.200 | [0.036, 0.624] | 73 | 14.6 |
| no exclusion change | 0/13 | 0.000 | [0.000, 0.228] | 5,861 | 0.0 |
| relaxation | 0/8 | 0.000 | [0.000, 0.324] | 304 | 0.0 |
| rewrite, no net change | 3/9 | 0.333 | [0.121, 0.646] | 354 | 118.0 |

Estimated false negatives **133**; estimated true positives 1,359; **recall ≈ 0.911**;
implied true population 1,491 against 1,642 detected.

**Report recall as a point estimate with the per-stratum intervals, not a single CI.**
The estimate is a weighted extrapolation and the per-stratum intervals are wide.

**89% of estimated false negatives originate in the `rewrite` stratum** — precisely where
§1.2 (generalisation) and §1.3 (compound revisions) predict the method is blind. The
quantitative estimate and the hand inspection agree, which is the strongest corroboration
available here.

### 6.3.1 What adjudicating the relaxation stratum found

The stratum initially showed 3/10 false negatives, contributing 41% of the estimate.
Reading all three closed it to 0/8:

- **V084** — five bare-name exclusions (`*\chrome.exe`, `*\firefox.exe`, …) replaced by
  three absolute paths, with two dropped. A genuine relaxation; rater error.
  **Worth citing in the discussion as the good-practice counter-example:** an author
  hardening forgeable bare-name exclusions into paths an adversary cannot occupy.
- **V085** — removes `SysWow64`, `system32`, `winsxs` while keeping `SysWOW64`,
  `System32`, `WinSxS`. **Case-variant deduplication**; Windows paths are
  case-insensitive, so nothing changed semantically. Neither S nor N.
- **V087** — six specific Citrix paths collapse to one `*\Citrix\System32\icast.exe`
  (broader) while `*:` → `C:` elsewhere (narrower). A compound revision containing a
  mechanism-3 generalisation.

**New limitation (7).** Case-variant deduplication is counted as relaxation, inflating
the relaxation count. Like the other undetected mechanisms this biases *against* the
hypothesis, so **5.4 : 1 is conservative.**

### 6.4 Disclosures

- **27 of 120 items (22.5%) were labelled unclear** and excluded from both estimates.
  The rate is high and indicates the suppression/relaxation boundary is genuinely hard to
  judge from diffs alone. Report it; do not suppress it.
- **Six labelling corrections** were made during disagreement adjudication (V004, V005,
  V057, V060, V084 to N; V085, V087 to U). V060 — an item with a byte-identical exclusion
  set labelled as a suppression — alone accounted for 452 of the 748 false negatives
  estimated in the first pass.
- **Precision-adjusted count.** At precision 0.828 the 1,642 detected suppressions imply
  ~1,359 true ones. Report 1,642 as detected alongside the validation metrics. The
  **ratio is more robust than the absolute counts**, since classification error affects
  numerator and denominator similarly — though note that *relaxation* precision was not
  separately measured, since relaxations entered the sample only as a negative stratum
  for suppression.
- **Adjudication also found one systematic detector fault**, correction 5 in §1: a
  catch-all selection predicate was counted as coverage growth. Fixed.
- **15 items were discussed with an AI assistant during labelling** (V001–V006,
  V020–V026, V044, V045) and are flagged `[supervised]` in `sample_labels.csv`. This
  must appear in the generative-AI disclosure.
- Single rater. **No inter-rater agreement is available**; a second rater on a subset
  would strengthen this materially and is the most valuable remaining addition.

## 7. Corroboration from commit messages

**Supersedes the 78% figure, which rested on the broken join described in correction 8.**

Commit subjects joined to revision steps by lineage and commit date. Of 1,642
suppressions: **1,203 match a unique same-day commit**, 439 fall on days with multiple
commits (reported separately, never folded in), none are unmatched.

Two vocabularies are counted separately, because they carry different evidential weight:

- **reason** — `FP`, `false positive`, `noisy`, `benign`, `legitimate`,
  `expected behaviour`. States *why* the edit was made. Nothing in the diff compels
  these words to appear.
- **mechanism** — `filter`, `exclude`, `exclusion`, `whitelist`, `allowlist`. Describes
  *what* the edit did, and therefore partly circular: a commit that adds a filter may
  simply say so.

| step class | n | reason | mechanism |
|---|---:|---:|---:|
| **suppression** | 1,203 | **30.9%** | 10.8% |
| relaxation | 186 | 15.6% | 5.4% |
| neither | 4,528 | **3.0%** | 1.5% |

**Enrichment over baseline: 10.3×** (30.9% vs 3.0%).

Three things this establishes:

1. **The corroboration is not circular.** Reason-language runs three times higher than
   mechanism-language in suppression commits. Maintainers write "false positive", not
   "add filter", so the agreement is not an artefact of the diff and the message
   describing the same act.
2. **The classifier separates two kinds of edit.** Suppressions carry twice the
   reason-language of relaxations (30.9% vs 15.6%), which the detector was not given any
   access to.
3. **The absolute rate is bounded by commit hygiene, not by the phenomenon.** Most Sigma
   commit subjects are terse ("update rule", "fix typo"). 30.9% is a floor on how often a
   suppression was motivated by a false positive, not an estimate of it.

**Report the ratio, not the percentage.** 30.9% invites "so 69% weren't about false
positives?" — which the data cannot answer. 10.3× enrichment is the defensible claim.

## 8. Comparison with prior work — clocks differ

Prior work reports a median of **4.8 days**: time between *edits to a rule*. These
figures are time to *reversal of a specific exclusion*. Different event, different
clock. Any side-by-side presentation must say so, or the contrast reads as a
three-order-of-magnitude error.
